# 孤独症儿童治疗建议问答系统 — 总体方案

> **状态：设计文档（v1，项目尚未编码）。** 本文档描述目标系统的功能设计、架构与技术栈，作为开发依据与结课汇报素材。落地后用真实结构更新标注 `(计划)` 的部分。

---

## 0. 重要定位与免责（系统的一等约束）

本系统是面向孤独症（ASD）儿童家长/教师/早期干预人员的**辅助信息参考工具**，基于权威文献给出**循证的、可溯源的**干预建议方向。

- **不是诊断工具，不替代专业医师/治疗师/特教评估。**
- 所有输出必须显式附带免责声明，并**标注每条建议的文献出处**。
- 拒答边界：涉及用药剂量、急症处理、明确诊断结论等高风险问题时，系统应拒绝直接给结论，转而建议线下就医，并说明原因。
- 这条定位不是"加在最后的提示语"，而是贯穿 Prompt 设计、输出格式、UI 提示的硬约束。

> 把"安全与可溯源"做成核心卖点，正好对抗 LLM 幻觉，也是本项目相对"简单复现"的创新与价值所在。

---

## 1. 项目背景与现实意义

- 孤独症干预高度依赖专业资源，但优质资源稀缺、地域不均，家长普遍面临"信息过载又无从判断权威性"的困境。
- 通用大模型直接问答存在**幻觉**和**来源不可查**的问题，在医疗场景风险高。
- 本系统用 **RAG** 把回答**锚定在用户提供的权威文献**上，并结合**具体孩子的成长报告**做个性化的、有出处的建议，兼顾权威性与针对性。

---

## 2. 核心创新点

1. **双输入 RAG 架构**：把"通用知识"与"个案情境"解耦——
   - 权威文献 → 持久向量知识库（共享、可复用）
   - 孩子成长报告 → 会话级个案上下文（私密、临时）
   两者在 Prompt 阶段融合：**"针对这个孩子的情况，权威文献怎么说"**。
2. **建议可溯源**：每条建议标注来源文献与位置，用户可点开原文核对。
3. **安全护栏 + 拒答机制**：医疗场景下主动收敛高风险问题，体现负责任的 AI 设计。
4. **可对比实验底座**：模型/Top-K/是否启用 RAG 可切换，支撑"模型能力分析"汇报。

---

## 3. 功能设计

### 3.1 文献知识库管理（离线链路）
- 上传权威文献（PDF / Word / txt），支持批量。
- 自动抽取文本 → 分块 → 嵌入 → 写入向量库，保留来源元数据（文件名、页码/章节）。
- 文献列表管理：查看已入库文献、删除、重建索引。
- （可选）给文献打标签（如"行为干预 / 语言 / 社交 / 家庭训练"），便于过滤检索。

### 3.2 个案咨询问答（在线链路，核心）
- **上传孩子成长报告**（评估量表结果、行为描述、发育里程碑等），作为本次会话的个案上下文。
- 输入问题（如"孩子3岁不进行眼神交流、无语言，家庭可以做哪些早期干预？"）。
- 系统流程：
  1. 解析成长报告，提炼关键画像（年龄、核心症状、已有评估）。
  2. 用"问题 + 个案画像"做向量检索，从文献库取 Top-K 相关片段。
  3. 拼装 Prompt（个案情境 + 检索片段 + 安全约束）交 LLM 生成。
  4. 输出**结构化建议**：建议方向、依据（带文献出处）、注意事项、何时需就医、免责声明。
- 多轮追问：在同一会话内保留个案上下文，可继续追问。

### 3.3 出处与可信度展示
- 每条建议旁标注引用编号，点击可展开对应文献原文片段与位置。
- 明确区分"来自文献的内容"与"模型的组织性表述"。

### 3.4 安全与合规
- 全局免责横幅 + 每次回答末尾免责声明。
- 高风险问题（用药、剂量、急症、确诊）触发拒答/转介模板。
- 个案数据隐私：成长报告默认**仅存于当前会话**，不进公共知识库；如需留存，单独加密/隔离存储并提示用户。

### 3.5 （汇报用）实验对比面板
- 可切换：模型厂商、Top-K、chunk 大小、是否启用 RAG（裸 LLM 对照）。
- 记录可复现的输入输出，导出为汇报证据。

## 4. 系统架构与数据流

理解本系统抓住**三条链路**：

**A. 文献入库链路（管理员/用户上传文献时，一次性）**
```
权威文献 → 文本抽取 → 分块 → 嵌入 → 写入 Chroma(向量 + 原文 + 来源元数据)
                                              [持久、共享知识库]
```

**B. 个案上下文链路（每次咨询会话，临时）**
```
成长报告 → 文本抽取 → 提炼个案画像(年龄/症状/评估) → 仅保留在会话状态
            (默认不写入公共向量库，保护隐私)
```

**C. 问答生成链路（每次提问）**
```
用户问题 + 个案画像 → 向量检索文献Top-K → 安全护栏校验
        → 拼装Prompt(个案情境 + 文献片段 + 免责约束) → LLM生成 → 带出处的结构化建议
```

**关键设计决策**
- **文献库 vs 个案报告分离**：文献是"知识"(持久/共享/可检索)，成长报告是"情境"(会话级/私密)。绝不把个案隐私数据写入公共向量库。
- **个案报告如何参与检索**：用报告提炼出的画像增强检索 query（提高命中相关文献），但报告原文作为上下文直接拼进 Prompt，而非检索目标。
- **分块策略与 Top-K 是效果主旋钮**，调参实验须记录在案。
- **模块边界清晰**：embedding、LLM、检索分层封装，便于单独替换做对比实验。

## 5. 技术栈（计划）

| 层 | 选型 | 理由 |
|----|------|------|
| 语言 | Python 3.10+ | 生态成熟 |
| 界面 | Streamlit | 最快出 demo，上传/聊天/出处展示都好做 |
| LLM 接入 | 国内 API 优先（DeepSeek / 智谱 GLM），OpenAI 兼容接口 | 访问方便、可切换做对比 |
| 向量库 | Chroma（本地持久化） | 轻量、零运维 |
| 嵌入模型 | API embedding 优先；本地可用 `bge-small-zh` | 中文友好 |
| 文档解析 | `pypdf` / `python-docx` / `unstructured` | 多格式抽取 |
| 元数据/记录 | SQLite | 文献清单、会话、实验记录 |
| 部署 | Docker → 云服务器 / Streamlit Cloud | 云计算课程结合点 |

> LLM 与 embedding 必须做成**可配置、可切换**，不把某一家硬编码进业务逻辑——这是"模型能力对比"汇报的关键。

## 6. 数据模型（计划）

**Chroma 集合**
- `literature`：权威文献分块。metadata：`source_file, page, section, tags, chunk_id`。

**SQLite 表**
- `documents(id, filename, upload_time, num_chunks, tags)` — 已入库文献清单。
- `sessions(id, created_at, child_profile_summary)` — 咨询会话（个案画像摘要，注意隐私）。
- `qa_logs(id, session_id, question, retrieved_chunks, answer, model, top_k, created_at)` — 问答留痕，兼作实验证据。
- `experiments(id, variable, value, fixed_config, question_set, result_path)` — 对比实验记录。

---

## 7. Prompt 设计要点（幻觉抑制核心）

System Prompt 固定包含：
1. 角色与边界："你是孤独症早期干预的循证信息助手，只能基于提供的文献作答。"
2. **强制溯源**："每条建议必须标注来源编号 [n]，无文献支持的内容不得给出。"
3. **拒答规则**：用药/剂量/确诊/急症 → 模板化转介。
4. **结构化输出**：建议方向 / 文献依据(带出处) / 注意事项 / 何时就医 / 免责声明。
5. "检索片段不足以回答时，明确说'现有文献不足以回答'，不要编造。"

User Prompt 拼装：`个案画像 + Top-K 文献片段(带编号与出处) + 当前问题`。

## 8. 建议目录结构（计划）

```
app.py                  # Streamlit 入口：文献管理 + 个案咨询 + 出处展示 + 实验面板
ingest/                 # 文献入库：抽取、分块、嵌入、写库
case/                   # 个案处理：成长报告解析、画像提炼
retrieval/              # 检索 + Prompt 拼装 + 安全护栏
llm/                    # LLM 与 embedding 客户端封装（可切换厂商）
config.py / .env        # 模型选择、API Key、Top-K、chunk 大小等可调参数
data/                   # Chroma 持久化、SQLite、上传的原始文件
docs/ 或 experiments/   # 开发记录、Prompt 版本、模型对比数据（汇报素材）
```

## 9. 开发里程碑（计划）

1. **M1 跑通最小闭环**：单篇文献入库 → 提问 → 带出处回答（先不接个案报告）。
2. **M2 加个案链路**：上传成长报告 → 画像提炼 → 融入 Prompt。
3. **M3 安全与出处**：免责、拒答护栏、出处高亮展示。
4. **M4 实验面板 + 数据沉淀**：模型/Top-K 可切换，留痕导出。
5. **M5 容器化部署 + 汇报材料**：Docker 上云，整理对比数据成报告/PPT。

---

## 10. 风险与边界

- **医疗伦理/法律**：明确"非诊断、辅助参考"，全程免责，高风险拒答。这是本项目能否成立的前提。
- **隐私**：成长报告含儿童敏感信息，默认仅会话内使用、不入公共库、不外传第三方（注意所选 LLM API 的数据政策）。
- **文献质量**：系统能力上限取决于上传文献质量；建议在 UI 提示"请上传权威来源（指南、同行评议文献）"。
- **过度依赖**：UI 反复提示这是参考工具，引导用户寻求专业评估。

## 11. 对应课程汇报的素材点

- **LLM 辅助开发方式**：记录用 Claude Code 做需求拆解、生成入库/检索代码、Prompt 迭代、调试的全过程。
- **模型能力分析**（用 `model-compare` 跑数据）：
  - 裸 LLM vs RAG：在孤独症问题上的幻觉率、出处可查性差异。
  - 不同模型/Top-K：回答质量与成本权衡。
  - 安全护栏前后：高风险问题的拒答表现。
- 所有实验"固定其余变量、保留可复现输入输出"，作为答辩证据。
