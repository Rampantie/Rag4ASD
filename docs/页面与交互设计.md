# 页面与交互设计方案

> **状态：设计文档（v1，未编码）。** 承接 @docs/系统设计方案.md，本文聚焦**功能结构、页面组织、各页面运行流程**，作为前端实现依据。落地后用真实组件名更新。
> 技术前提：Streamlit 多页应用（`pages/` 目录自动生成侧边栏导航）。

---

## 1. 功能结构总览

把系统能力拆成 5 个功能模块，再映射到页面：

```
孤独症儿童治疗建议问答系统
├─ M1 文献知识库管理      → 页面②  上传/入库/查看/删除权威文献
├─ M2 个案咨询问答(核心)   → 页面③  传成长报告 + 提问 → 带出处建议
├─ M3 历史与会话回溯      → 页面④  查看过往咨询记录
├─ M4 模型对比实验(汇报用) → 页面⑤  切换变量跑对比、导出证据
└─ M5 配置与免责          → 页面①+侧边栏  模型/Top-K/chunk、全局免责
```

每个咨询的两类输入严格分离（见 CLAUDE.md）：**文献=持久知识库**（页面②管理），**成长报告=会话级上下文**（页面③临时上传，不入公共库）。

---

## 2. 页面组织（导航结构）

Streamlit 侧边栏导航，5 个页面 + 全局元素：

| 页面 | 文件(计划) | 角色 | 优先级 |
|------|-----------|------|--------|
| ① 首页 / 总览 | `app.py` | 项目说明、免责声明、知识库状态 | M5 |
| ② 文献知识库 | `pages/1_文献知识库.py` | 管理权威文献（离线链路） | M1 |
| ③ 个案咨询 | `pages/2_个案咨询.py` | **核心**：问答+出处（在线链路） | M2 |
| ④ 咨询历史 | `pages/3_咨询历史.py` | 回溯过往会话与问答 | M3 |
| ⑤ 实验面板 | `pages/4_实验对比.py` | 模型/Top-K 对比，汇报证据 | M4 |

**全局元素（每页都有）**
- 侧边栏顶部：固定**免责横幅**（"本系统仅供参考，不替代专业诊疗"）。
- 侧边栏底部：当前模型、Top-K、知识库文献数等状态指示。
- 会话状态 `st.session_state`：保存当前个案画像、对话历史、配置。

## 3. 各页面运行流程

### 页面① 首页 / 总览

**目的**：落地说明 + 安全告知 + 引导。

**布局**
```
┌──────────────────────────────────┐
│ 标题 + 一句话定位                  │
│ ⚠ 免责声明卡片（醒目）             │
│ 使用三步引导：① 传文献 ② 传报告+提问 ③ 看带出处建议 │
│ 知识库状态：已入库 N 篇文献         │
│ [去管理文献] [开始咨询] 按钮        │
└──────────────────────────────────┘
```

**运行流程**
1. 加载时读取 SQLite `documents` 表 → 显示已入库文献数。
2. 渲染免责声明（首次访问可要求勾选"我已知悉"再放行核心功能，作为合规设计）。
3. 按钮跳转到页面②/③。

---

### 页面② 文献知识库管理（离线入库链路）

**目的**：构建/维护共享知识库。

**布局**
```
┌── 上传区 ──────────────┐  ┌── 已入库文献列表 ─────┐
│ 拖拽 PDF/Word/txt(多选) │  │ 文件名 | 块数 | 标签 | 删除 │
│ [标签输入] [开始入库]   │  │ ...                       │
└────────────────────────┘  └───────────────────────────┘
        ↓ 入库进度条 + 日志
```

**运行流程（点击"开始入库"后）**
1. 接收上传文件，存到 `data/raw/`。
2. **抽取**：按格式调用 `pypdf`/`python-docx` 提取文本。
3. **分块**：按配置的 chunk 大小/重叠切分，每块附来源元数据（文件名、页码/章节、标签）。
4. **嵌入**：调用 `llm/` 封装的 embedding，得到向量。
5. **写库**：写入 Chroma `literature` 集合（向量+原文+元数据）；同时在 SQLite `documents` 记录文件名、块数、标签。
6. 实时进度反馈，完成后刷新右侧列表，报告"写入 X 块、来自 Y 个文件"。
7. **删除**：从列表删某文献 → 同步删 Chroma 中对应 chunk + SQLite 记录。

**关键校验**：入库后确认每块都带来源元数据（出处可溯源的前提），缺失要报警。

### 页面③ 个案咨询问答（核心，在线生成链路）

**目的**：结合具体孩子情况 + 文献，给出带出处的建议。这是产品的主舞台。

**布局**
```
┌── 左：个案上下文 ──────┐  ┌── 右：对话区 ──────────────┐
│ 上传成长报告(PDF/文本)  │  │ [历史对话气泡...]            │
│ → 提炼的个案画像卡片：  │  │ 用户问：...                 │
│   年龄/核心症状/已评估  │  │ 系统答：                    │
│ [清空会话]             │  │  · 建议方向                 │
│                        │  │  · 文献依据 [1][2]（可展开） │
│ 配置：模型|Top-K(可调)  │  │  · 注意事项 / 何时就医       │
│                        │  │  · ⚠免责声明                │
│                        │  │ [输入框] [发送]             │
└────────────────────────┘  └────────────────────────────┘
```

**运行流程**

*阶段一：建立个案上下文（上传报告后，每会话一次）*
1. 上传成长报告 → 抽取文本（**不写入向量库**，仅存 `st.session_state`）。
2. 调 LLM 提炼**个案画像**（年龄、核心症状、已有评估结论）→ 显示画像卡片供用户确认/修正。

*阶段二：单轮问答（每次提问）*
1. 用户输入问题。
2. **安全护栏前置校验**：命中高风险（用药/剂量/确诊/急症）→ 直接返回拒答转介模板，不走检索。
3. **构造检索 query**：问题 + 个案画像关键词 → 嵌入。
4. **向量检索**：从 `literature` 取 Top-K 相关片段（带出处编号）。
5. **拼装 Prompt**：System(角色+强制溯源+拒答+结构化输出) + 个案画像 + Top-K 片段 + 问题。
6. **LLM 生成** → 解析为结构化建议。
7. **渲染**：建议方向 / 文献依据(点 [n] 展开原文与出处) / 注意事项 / 何时就医 / 免责声明。
8. **留痕**：把 question、检索片段、answer、model、top_k 写入 SQLite `qa_logs`。
9. 多轮：保留对话历史与个案画像于会话状态，可继续追问。

*结束*：用户点"清空会话" → 清除个案画像与对话历史（隐私，不残留）。

---

### 页面④ 咨询历史

**目的**：回溯过往问答（也是 demo 时展示效果的素材）。

**运行流程**
1. 读取 SQLite `qa_logs`（按会话/时间分组）。
2. 列表展示：时间、问题摘要、所用模型。
3. 点击某条 → 展开完整问答 + 当时检索到的文献片段。
4. （隐私）个案画像只显示脱敏摘要；提供"删除记录"。

---

### 页面⑤ 实验对比面板（汇报证据生产线）

**目的**：服务"模型能力分析"汇报，跑可复现的单变量对比。

**布局**
```
┌── 实验配置 ──────────────────────┐
│ 固定问题集（下拉/编辑）            │
│ 对比变量：○模型 ○Top-K ○chunk ○是否RAG │
│ 各取值勾选 | 其余固定值显示        │
│ [运行对比]                        │
└───────────────────────────────────┘
        ↓
┌── 结果对比表 ────────────────────┐
│ 问题 | 配置A答案 | 配置B答案 | 出处? | 评分 │
│ [导出到 experiments/]             │
└───────────────────────────────────┘
```

**运行流程**
1. 选定**对比变量**及取值，其余变量固定（单一变量原则）。
2. 加载固定问题集。
3. 对每个(问题 × 配置)跑一遍问答链路，收集：回答、检索片段、是否带正确出处。
4. 并排渲染对比表，支持人工打分。
5. **导出**：把"配置+完整输入输出+结论"写到 `experiments/`，文件名体现变量（如 `compare_topk.md`）。

> 此页直接对应 `model-compare` skill 的逻辑，可由它驱动。

## 4. 会话状态与数据流（贯穿全局）

`st.session_state` 关键字段：
- `child_profile`：当前个案画像（页面③，清空即删）。
- `chat_history`：当前会话对话。
- `config`：model / top_k / chunk_size（侧边栏可调，影响③⑤）。

持久化：
- **Chroma `literature`**：文献向量（页面②写，③⑤读）。
- **SQLite**：`documents`（②）、`qa_logs`（③④）、`experiments`（⑤）。

---

## 5. 实现优先级建议（对应里程碑）

1. **先做页面③的最小版**（甚至先不接成长报告）：能"提问→检索→带出处回答"即闭环 = M1。
2. 补页面②（文献管理）让知识库可维护 = 已隐含在 M1。
3. 页面③接入成长报告与个案画像 = M2。
4. 安全护栏 + 出处展示打磨 = M3。
5. 页面⑤实验面板 + 页面④历史 = M4。
6. 首页①免责引导收尾 + 部署 = M5。

> demo 阶段：页面③ > 页面② > 页面⑤ > 页面① > 页面④。先让核心闭环跑起来，其余增量补。
